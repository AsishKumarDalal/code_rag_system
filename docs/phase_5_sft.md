# 📘 Phase 5 — SFT: Teaching the Behavior (Theory)

## 1. Where we are in the storyline

```
Phase 3: CPT            Phase 4: RAG            Phase 5: SFT           Phase 6: RLVR
knowledge → weights  ·  library (no training) · behavior → weights · judgment → weights
     ✔ done                built later             ◀ WE ARE HERE
```

**One-sentence goal:** after CPT the model *knows more* but still behaves like a plain
chatbot — it answers instantly, never decomposes, never searches, never cites.
Phase 5 installs the **work loop**: think → plan → search when missing → read →
solve → compose with citations.

The doctor analogy, continued: Phase 3 read the textbooks into long-term memory
(knowledge). But knowing medicine is not method. Phase 5 is the **apprenticeship
year** — the doctor shadows a senior physician and copies *how* they approach a
case: take a history, order the right test, check the reference, only then
diagnose. Nobody memorizes new textbooks during the apprenticeship — the
*knowledge stays; the method is learned*.

---

## 2. What kind of learning this is — imitation, not knowledge

SFT (Supervised Fine-Tuning) is **behavior cloning / imitation learning**.

| | Phase 3 CPT | Phase 5 SFT |
|---|---|---|
| Task | predict next token on domain text | predict next token on *expert decision traces* |
| Signal | "code text looks like *this*" | "a good problem-solver *acts* like this" |
| Learns | vocabulary, facts, intuitions | **when to plan, when to search, how to cite, how to compose** |
| Data | 300M tokens of corpus | 50–80k expert traces (~150–300M tokens) |
| Result | smarter model, same behavior | same knowledge, new workflow |

Formally: the model is a policy `π(action | situation)`. The *situation* is the
question plus everything generated so far. The *action* is the next token of the
trace. Expert traces are the demonstrations; we maximise their likelihood.
That's it — behavior cloning. All the magic is in **what counts as an expert
trace**, which is where most of this document lives.

**Why SFT must come BEFORE RL (Phase 6):** RLVR (GRPO) improves a policy by
sampling many attempts and rewarding the good ones. If the policy can't yet
produce valid loop format, almost every sample is broken → reward ≈ 0 everywhere →
no learning signal. SFT installs the grammar and a decent starting policy; RL
then sharpens *judgment* on top of it. Order is not a preference — it's what makes
Phase 6 possible.

## 3. The loop grammar — the exact format the model must learn

This is the **contract between the model and the harness** (the harness is the
Python wrapper that runs at deployment; it intercepts `<search>…</search>`,
executes retrieval, injects `<obs>…` and continues generation). The full trace
template every SFT episode must follow:

```text
<question>{user_task}</question>
<plan>{decompose into checked sub-problems}</plan>
<search>{precise retrieval query for sub-problem A}</search>
<obs>{harness injects top-5 retrieved chunks, each with a cited file-tag}</obs>
<search>{precise retrieval query for sub-problem B}</search>
<obs>{harness injects …}</obs>
<thinking>{solve each sub-problem using retrieved evidence, cite each claim}</thinking>
<answer>{final answer, composed coherently, inline file-tags on claims}</answer>
```

Notes:

- `<obs>` is **never generated by the model** — it appears in training traces (so
  the model learns to *wait for* and *consume* observations) and is injected by
  the harness at deployment. In RL later, the environment plays this role too.
- Every claim in the final answer should carry an inline file-tag → every answer
  is attributable. This is the product promise.
- The grammar is deliberately **XML-ish and consistent** — easy to intercept,
  easy to parse, easy to validate, easy to RL-reward (format violations are
  cheaply detectable).

### What each block teaches

| Block | Skill | Failure without it |
|---|---|---|
| `<plan>` | decomposition: big question → sub-problems | model dives in, misses constraints, hallucinate-guesses |
| `<search>` | query writing: precise, identifier-rich | vague queries → garbage retrieval |
| `<obs>` (consume) | evidence reading: use it, cite it | model ignores retrieval, answers from prior |
| `<answer>` | composition + inline citations | correct steps, incoherent delivery, no provenance |
| `<search>` (again) | multi-hop persistence | gives up after one hop |

**When NOT to search** is taught too: trivial questions need `plan →`
short-thinking → answer with zero
must be present (the trace starts) — teaches selective retrieval, not pestering.

## 4. Where expert traces come from — the three memories of behavior data

| Source | What it is | Quality | Role |
|---|---|---|---|
| **Teacher** (synthetic distillation) | traces written/run by a stronger existing model | uniform format, plausible reasoning | volume |
| **Human** | hand-made gold traces | best logic, few, expensive | correctness anchors |
| **Self** | model's own outputs kept only when verifier agrees | needs a verifier → that's Phase 6 | later |

Phase 5 leans entirely on **public teacher data** — two datasets, chosen
because together they cover both halves of the skill:

### 4.1 `corag/multihopqa` — the RAG-loop core (the important half)

CoRAG-style chained-retrieval data ships **readmade decomposition**: each item is
a question with literal `subqueries[]` and `subanswers[]` plus retrieved context
that answers them in order, ending in the final answer. A multi-hop question
like *“Which film by the director of X came out first: A or B?”* decomposes into
two sub-questions with two retrievals — the trace structure we want, already
factored.

We **reformat** each item into our grammar: question → `plan` (from the
subqueries) → `search`(subquery₁) → `obs`(its context) → … →
`answer` (final answer with file-tags). No model is called in LoRA training —
SFT is pure supervised token prediction.

### 4.2 `nvidia/Nemotron-Cascade-SFT-Stage-2` — loop fluency beyond RAG

A large public SFT corpus with reasoning, **tool-calling**, and code/SWE subsets.
Its tool-calling traces teach the general skill of *interleaving
actions and thought* mid-problem; the code subsets keep domain-flavored prose in
the loop (helping general retention without washing out the CPT layer).

Choice signals for proportions: ~50–80k episodes total is enough to lock a fixed
format when all episodes share one grammar. Chronic under-represented cases
(e.g., no-search episodes, 2-hop, 3-hop) get explicit quotas, mirroring
the prep mixing logic (Phase 3 §17-style) — curriculum: tool-calling basics →
2-hop RAG → 3-hop RAG → domain-flavored.

## 5. From raw items to training episodes — the build contract

Same engineering philosophy as the CPT prep: **verify → slice → clean →
dedup/decontaminate → pack → bank (HF is ground truth)**:

1. **verify** each raw item against its true schema (fail-soft per source;
   crash on schema drift — not silently accept bad rows);
2. **reformat** → one JSONL row per episode: `{"messages":[…], "meta":{source}}`;
3. **dedup** — repeated questions collapse to one episode each (sha on question;
   exact-dup collapse like prep's sha-256 gate);
4. **decontaminate** — re-use the Phase-3/backend machinery: 13-gram check against
   HumanEval / MBPP / GSM8K (any *_test surface we will eval on* — same
   `EVAL_SETS`), so nothing in training overlaps with honest evaluation (this is
   the **honest-eval discipline** from Phase 3 §26, applied to behavior data);
5. **quota mix** per plan (CoRAG multihop + nemotron subsets in set proportions),
   curriculum ordering preserved in file order;
6. **split** train/val (val = few hundred episodes; val drives epoch-select);
7. **pack** — episodes concatenated to fixed 6–8k-token frames *with a valid
   `<question>` boundary alignment* (no mid-episode frame cuts);
8. **bank** — `data/sft/episodes_*.jsonl` + `sft_manifest.json` to the HF repo;
   local disk keeps < 1 GB; manifest records source, split, counts, per-source
   episodes, and content fingerprint.

Episode quality gates (each gate drops rows, logged with counts):

| Gate | Bad | Catches |
|---|---|---|
| **format validity** | regex/grammar attempt to *re-invent* format | missing tag, empty plan, answer-with-cites-but-no-obs, etc. |
| **length bounds** | episodes must be ≤ 4 usable grams of *thinking* | runaway generation |
| **obs counted** | `obs` injected for every `search` (harness would inject one) | mismatched search/obs pairs |
| **answer non-empty** + tag match | answer text must reference ≥1 priority file-tag for RAG-relevant episodes | ungrounded answers |
| **language** | English-dominant teas lines | stray noise rows |

Tracks two counts: raw → built, and **reason/string for every drop count**: you
should always be able to see *why* a row died (the pattern the user demanded in
Phase 3).

## 6. Training mechanics — LoRA on top of `cpt.v1` (this matters a lot)

### 6.1 Fresh LoRA, frozen base

- Load **`cpt.v1`** (the CPT result — full merged model from Phase-3), freeze it,
  attach a **new LoRA r=128 all-linear adapters** and train *only the adapters*.
- Why not full fine-tune? **The freeze is the preservation trick.** Behavior
  training with small data can sand general ability off a full model (SFT
  catastrophically forgetting). Frozen base = Phase-3 knowledge physically
  cannot be washed out; the adapters learn the *workflow* on top.
- Why fresh adapters rather than continue Phase-3's? Phase 3's adapters encode
  domain-token statistics; Phase 5's encode *decision* statistics. Keeping them
  separate keeps the lineage honest (`cpt.v1 ++ sft-adapters = sft.v2`) and lets
  us re-merge — the two-memories principle again, now in adapter form.

### 6.2 The three knobs that matter

| Knob | Value | Why not bigger/smaller |
|---|---|---|
| **Loss masking** | CE loss **only on generated tokens** (`<plan>` → `<answer>`); `question`/`obs` tokens are context — pure mask −100 | computing loss on questions would pull learning toward *memorizing inputs*, the classic SFT overfit |
| **LR** | **1e-5 – 2e-5** (LoRA), cosine decay, 3% warmup, wd 0 | format learning is fragile at high LR — too big and grammar wobbles, too small and it churns forever; 2–3 epochs is optimal |
| **Epochs** | 2 (3rd epoch almost always overfits format, drops the diversity of plans) | behavior data saturation comes fast — stop early, validate |

### 6.3 The in-loop scoreboard (val probes every ~½ epoch)

- **format-validity %** on val episodes (regex over generated trace) — target
  ≥ 95%, the gate below which nothing else matters;
- **answer EM / F1** on val (multi-hop test piece held out of train);
- **citation presence** ≥ 90% of `<answer>` claims carrying file-tags;
- **no-search rate** — sanity band 30–60% (healthy mix indicates selective retrieval rather than search-pestering or search-avoidance);
- **forgetting probes** — a fixed set of *general* prompts (non-domain): watch
  for catastrophic style collapse (the replay protection in the mix + frozen
  base keeps this boring).

### 6.4 Checkpointing + selection

Same kill-safe pattern as the CPT train: hourly ckpt (adapters + optimizer +
data position → HF), auto-resume from newest; **best-ckpt selection by
format-validity on val** (a run where the loss dips but format breaks is
worse than a run where neither); ship as `sft.v2` with parent-link metadata
(`base: cpt.v1`, data fingerprint, recipe, val scores) banked to HF.

### 6.5 Budget

~50–80k episodes ≈ 150–300M tokens; LoRA on 4B ≈ same per-token compute as CPT;
**~10–16h on one v5e-8 session** (or 2–3 GPU sessions via QLoRA escape) — the
same session-resume safety covers all of it.

## 7. Known failure modes — what breaks SFT runs (and the fix)

| Failure | Symptom | Fix |
|---|---|---|
| **Format lock** | model uses the tags in *every* chat (even normal QA) | include clean non-loop chat episodes (Nemotron subsets) — teach format as a *tool drawer*, not the only drawer |
| **Search pestering** | `<search>` ×6 for a "what is X" question | no-search trivial episodes in the mix; reward structure in Phase 6 finishes this off |
| **Obs hallucination** | model *invents* the `<obs>` content | loss-masked obs tokens + harness-injection datas only; traces must have obs every search |
| **Plan theater** | verbose plans encoding nothing actionable | trim plans in training data; length gate on plan vs answer |
| **Citation drought** | answer without file-tags | citation-presence gate on data build + val probe |
| **The overfit epoch** | val EM up at first, format-validity then craters | best-checkpoint selection (see 6.4) — stop, don't hope |

---

## 8. Success gates — when does Phase 5 end?

A combination of quantities over val (report all five, pass all five):

1. format-validity ≥ 95%;
2. multi-hop answer EM/F1 ≥ ~:  baseline bar from the plain `cpt.v1` pilot without loop (the *delta* is what SFT buys);
3. citation presence ≥ 90%;
4. no-search rate inside the 30–60% band;
5. forgetting probes: general prompts remain fluent & non-loop-style.

Then and only then: Phase 6 — GRPO with verifiable rewards (unit-test-pass
rewards on code episodes, grounded-answer rewards on RAG episodes). The SFT
policy is the starting point GRPO improves; its exploration space is now the
*grammar we installed*.

**Artifacts this phase banks:** `data/sft/episodes_*.jsonl` + `sft_manifest.json`
(data leg) · `ckpt/sft/step_NNNNNN/` (training leg) · `models/sft.v2/`
(ship). Lineage: `base → cpt.v1 → sft.v2 → rl.v3` (every ckpt keeps its parent
link — the provenance rule).
